TRUST BOUNDARY

The server owns deadlines, permissions, answer state, and scoring. Clients display data and send actions; they do not decide the result.

Talking point: “We keep the network programming in the C server. The GUI connects directly over TCP, so we do not need an HTTP or WebSocket gateway. SQLite is local to the server process in the first version.”
03 · Application-layer protocol

One JSON message
per TCP line.

04 / 09
JSONL · TCP stream · UTF-8 · LF 0x0A
→ client request
{"type":"ANSWER_SET","request_id":42,"data":{"question_id":8,"choice":"B"}}\n

← server response
{"type":"RESPONSE","request_id":42,"ok":true,"data":{"saved":true}}\n

\n is the visible notation for one LF byte (0x0A).
01
Frame the byte stream

Buffer partial reads until `\n`; split multiple messages from one read.

02
Correlate requests

`request_id` matches a response to its request; errors return stable codes.

03
Protect scoring

Question delivery omits the correct choice. Only the server calculates scores.

04
Handle stream I/O

Use receive buffering and `send_all()` for partial reads and writes.

Talking point: “TCP has no message boundaries. We chose JSON Lines because it is easy to inspect during development. The server must still handle data split across reads or several JSON messages arriving together.”
